# 2.3.0 QA notes

These are known behavior edges from the action API migration. They are not part of the original
shelf crash fix and are listed here for manual QA.

## Shelf

- Two guests racing the same compartment: if an authoritative `(None, 0)` arrives before an
  accepted add's response, the predicted item is handed back on the clear. The guest can keep one
  local item the host also counts. It logs; reconcile the compartment.
- A router-level refusal (handler threw or sender was unauthorized) answers with the framework
  decision payload, so `OnMerge` has no stock to apply. It logs; the next state for the
  compartment reconciles it.
- A full hand parks the returned item as a loose pickable object in front of the player instead of
  calling `AddHoldItemToFront` past the transform list. Check the pickup appears and survives a
  scene reload.
- Held-box shelf removal carries the destination box locally; the box's own channel still
  replicates its contents. Check the box contents and shelf counts after a rejected take.
- Vanilla trims the saved hold list to 8. The mod now clamps returns to the real hold-transform
  list; check a 9-10 item hand after a save/load.

## Not fixed in this change (existing issues)

- Join baseline ordering: a guest can act while `Transferring`; an older baseline can arrive after
  a newer delta. Reliable ordering does not fix host send-order.
- Register: an older authoritative state can rebuild the station/carrier instead of waiting for
  the pending local action. It is visual/perf, not a divergence.
- Workbench exact-item identity is type/count based; a respawn can replace the exact item object.
- Card/grading claims and trade card deltas depend on the host-canonical player identity; verify
  an accepted/rejected hand-off leaves no duplicate or ghost card.

## Migration behavior checks

- `INetMessage` is for one-way/non-predicted state and notifications. Every discrete world
  interaction is an `ActionMessage` with `OnUndo`/`OnMerge`.
- Every predicted shared-state action carries the host's post-action state on accept and reject.
- `OnUndo` reverses the prediction; `OnMerge` applies the response state and settles exactly once.
- No action keys, follower replay, `OnApply`, `ActionLedger` in module code, or connection-id
  sends remain.
- A payload-less `ActionOutcome.Applied()`/`Reject(reason)` still settles through the internal
  `ActionDecisionMessage`.

## Tests

The test suite is not part of this migration pass. The user owns the test design and execution.
